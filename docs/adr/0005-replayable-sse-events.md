# ADR-0005：持久化事件日志与可回放 SSE

- 状态：Accepted
- 日期：2026-08-19

## 上下文

Agent 是长任务，Web 刷新、RN 切后台和网络切换都会中断连接。只推送实时 Token 或只轮询 Run 状态，无法可靠恢复执行时间线和工具状态。

## 决策

- 每个 Run 的事件使用数据库分配的单调递增 `sequence`。
- 事件先持久化，再推送给在线 SSE 订阅者。
- 客户端保存最后已应用序号，重连时请求 `after=lastSequence`。
- 客户端 Event Projector 按 `(runId, sequence)` 去重，并将事件投影为 UI 状态。
- REST 返回领域快照，事件流提供过程；事件不替代 Run/Approval 查询。

## 后果

- Web 与 RN 可以共享协议并恢复进度。
- 需要定义事件版本、保留策略和向后兼容规则。
- 多实例部署时需要数据库通知或消息基础设施；在单实例里程碑中先不引入 Redis。

## 未选择方案

- WebSocket：当前交互主要是服务端单向推送，连接恢复仍需要事件日志。
- 仅轮询：实时性和过程可见性不足。
- 只发送模型 Token：无法表达节点、工具、Evidence、审批和失败状态。

## 验证

- 断线期间产生的事件能在重连后完整补发。
- 历史与实时事件重叠时，UI 不重复、不倒退。
- tenant-b 无法订阅 tenant-a 的事件。
- 页面刷新后时间线与未刷新前投影一致。
