# 实施里程碑

里程碑按能力闭环划分，不按技术组件数量划分。当前实现状态和简历表述必须以里程碑验收结果为准。

## M0：设计基线与原型审计

### 目标

冻结产品范围、架构边界、技术决策和验收标准，确认现有第一阶段代码只是内存原型。

### 交付物

- PRD、架构边界、ADR、里程碑和验收标准。
- README 明确“已实现”和“目标设计”。
- 现有 Runtime、Registry、Risk Agent、Event Store 测试保持通过。
- 建立 Git 仓库并提交设计基线，后续变更可追踪。

### 退出门槛

- 文档之间术语、技术选型和阶段划分一致。
- 所有目标能力均能映射到验收项。
- 不在简历中使用尚未实现的目标能力。

## M1：可靠 Runtime 与多租户基础

**状态：工程闭环已完成（2026-08-19）。**

### 目标

将进程内原型升级为可持久化、可恢复、可授权的执行内核，暂时保留确定性风控逻辑。

### 实施顺序

1. 增加 PostgreSQL、Drizzle Schema 和迁移。
2. 抽象并实现 Run、Event、Approval、Evidence、Tool Invocation、Idempotency Repository。
3. 将 LangGraph checkpoint 接入 PostgreSQL，审批改为真正的暂停和恢复。
4. 使用 JWT 建立 `IdentityContext`，增加 Role、Scope 和对象权限接口。
5. 将写工具幂等从内存缓存改为数据库唯一约束和状态记录。
6. 将事件改为先持久化后 SSE 推送，并保持 `after=sequence` 回放。
7. 增加故障注入、跨租户和并发审批集成测试。

### 明确不做

- 不接真实模型和 Qdrant。
- 不开发 Web 页面。
- 不引入 Redis 或消息队列。

### 退出门槛

- 服务重启后可读取并恢复等待审批的 Run。
- 两个并发审批请求最多产生一次整改任务。
- API、事件、审批和工具的跨租户负向测试全部通过。
- 当前 8 个测试迁移后继续通过，并新增持久化集成测试。

### 当前验收结果

- 已通过：PostgreSQL Schema/迁移、Repository 接线、JWT Claims、Scope、`interrupt()`/`Command(resume)`、持久化 checkpoint、事件回放、Approval 原子竞争、工具审计与幂等。
- 已通过：状态转换与 Run 更新事务提交；审计记录包含操作者、原因和时间，跨租户查询被拒绝。
- 已通过：对象权限策略在工具执行前按 `appName/metaName/action/objectId` 判断，越权时工具体不执行。
- 已通过：API 启动自动扫描已审批未完成 Run，依据审批身份快照和 checkpoint 恢复，崩溃窗口不产生重复写回。
- 已通过：真实 PostgreSQL 17 上 6 个测试文件、22 个测试；包含重建 Runtime 恢复、10 路并发事件、双审批竞争和写回后故障恢复。
- 结论：可以表述为“实现可靠 Runtime 核心链路”；真实 PaaS 权限客户端、多副本恢复租约和生产规模仍不在完成范围内。

## M2：可演示的风控业务闭环

**状态：进行中，Model Provider、动态 Loop 与 RAG 后端已完成（2026-08-19）。**

### 目标

完成真实模型、真实知识检索和 Web 人机协作，使风控 Agent 达到主项目演示标准。

### 实施顺序

1. 抽象 Model Provider，提供确定性测试实现和真实模型实现。
2. 将固定 `collect` 改为 `plan -> collect -> evaluate -> replan` 受约束动态 Loop。
3. 实现文档上传、解析、Chunk、Embedding、Outbox 和 Qdrant 索引。
4. 将制度检索结果转换为包含文档版本与 locator 的 Evidence。
5. 使用结构化输出生成 Finding，并执行引用、覆盖率和规则校验。
6. 建设 React + Vite 工作台：任务列表、创建任务、Run 详情和审批。
7. 使用 TanStack Query 管理服务端状态，Zustand 实现事件投影和重连游标。
8. 建立脱敏风控与检索评测集，生成第一版指标报告。

### 当前进展

- 已完成：通用结构化 Model Provider、确定性测试 Provider、OpenAI Responses API Provider。
- 已完成：`plan -> collect -> evaluate -> replan` 状态图，最多三轮，成功工具不重复。
- 已完成：未知工具、写工具、无关工具和超预算计划由确定性策略拒绝并产生 `plan.rejected` 事件。
- 已完成：模型生成候选 Finding，Evidence 引用仍由确定性节点校验。
- 已完成：Markdown 文档版本、Chunk、确定性/OpenAI Embedding Provider、PostgreSQL Outbox 与 Qdrant 派生索引。
- 已完成：租户过滤、活动版本二次校验、权限标签过滤，以及包含文档版本、Chunk、章节和行号的制度 Evidence。
- 已完成：Qdrant 故障重试、陈旧任务锁回收和归档版本乱序任务跳过。
- 待完成：真实模型与真实 Qdrant 评测、Web 工作台和事件投影。

### 明确不做

- 不做拖拽工作流和通用 Agent 配置后台。
- 不接 RNModules，不实现第二 Agent。
- 不为展示而增加动画或无业务价值页面。

### 退出门槛

- 可在浏览器完成发起、动态取证、查看 Evidence、审批和整改写回。
- 至少有一个案件触发补充取证 Loop，一个案件触发人工补充，一个案件正常一次完成。
- tenant-a 与 tenant-b 使用不同制度，检索和报告无交叉。
- 刷新页面、断开 SSE 和重启 API 后任务状态与时间线可恢复。
- 检索、引用和任务指标达到验收标准中定义的目标。

达到 M2 后，可以在简历中将其描述为“项目风控 Agent 与工作台”，但暂不强调平台已被多业务验证。

## M3：PaaS 平台复用证明

### 目标

将已有 RN PaaS 经验转化为项目差异点，证明 Runtime 可以跨业务和跨终端复用。

### 实施顺序

1. 研究 RNModules 业务对象元数据、对象权限和注册扩展机制。
2. 定义从 PaaS 元数据到 Tool Schema 的生成规则和字段脱敏策略。
3. 实现 MCP Server 适配层，所有执行仍通过 Tool Registry。
4. 实现框架无关 RN Agent SDK：JWT、Run、SSE、补发和生命周期恢复。
5. 在 RNModules 或独立示例中完成风险摘要和移动审批接入。
6. 实现轻量合同合规 Agent，复用 Runtime、Evidence、Approval 和工作台时间线。
7. 增加平台复用测试和架构依赖检查。

### 退出门槛

- 至少一个工具由元数据生成 Schema，而非手写全部字段。
- 同一工具通过内部调用和 MCP 调用得到一致的权限、幂等和审计行为。
- RN 切后台并恢复后不丢事件、不重复创建 Run。
- Contract Agent 接入不修改 Runtime 领域模型和事件内核。
- Web 可使用同一通用时间线展示两个 Agent。

达到 M3 后，才可以在简历中使用“企业 Agent Runtime 与 PaaS 智能业务执行平台”的完整定位。

## M4：面试交付与评测固化

### 目标

让项目可以在 30 至 60 分钟面试中被验证，而不是只靠口头包装。

### 交付物

- 一键本地启动和固定演示数据。
- 5 至 8 分钟标准演示脚本和关键页面截图。
- 架构图、数据模型图、动态 Loop 图和故障恢复时序图。
- 检索、引用、恢复、隔离、延迟和成本评测报告。
- 关键 ADR 与“为什么不用其他方案”的回答。
- 与代码真实完成度一致的中英文简历项目描述。

### 退出门槛

- 新环境按 README 可以完成启动、迁移、索引和演示。
- 自动化检查全部通过，无需手动修改数据库状态。
- 任一简历指标均可追溯到评测脚本和结果文件。
- 能明确说明现有限制，不宣称生产规模或未测试的性能。

## 实施优先级原则

1. 先证明正确性和恢复，再做智能化。
2. 先做完整垂直闭环，再证明平台复用。
3. 每个技术组件必须对应业务问题和验收项。
4. 没有代码、测试或演示证明的能力，不进入简历成果。
